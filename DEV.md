# Credisearch: Developer Reference

Personal reference for running, changing and deploying Credisearch.
For how the ML works, see [ML.md](ML.md).

---

## 1. What runs where

| Piece | Where | Notes |
|---|---|---|
| FastAPI backend + ML | `backend/app/` | One Python app, deployed as a Vercel serverless function |
| Search UI | `backend/app/static/index.html` | Served by FastAPI at `/`; plain HTML + JS, no build step |
| API docs | `/docs` | Auto-generated by FastAPI (Swagger) |
| Hosting | Vercel project `credisearch_vercel` | Auto-deploys on every push to `main` |
| Live URL | https://credisearchvercel.vercel.app | |

## 2. Project structure

```
backend/
├── app/
│   ├── main.py                    # FastAPI app: "/", "/health", includes search router
│   ├── api/routes/search.py       # GET /search: fetch sources -> English filter -> ML -> log -> response
│   ├── api/routes/history.py      # GET /history, /history/{key}, /history/events/recent, /cron/log-prices
│   ├── core/config.py             # reads API keys from env / .env
│   ├── models/price.py            # PriceItem, ProductGroup, SearchResponse (pydantic)
│   ├── services/
│   │   ├── api_clients/           # one file per price source
│   │   │   ├── serpapi.py         #   SerpAPI Google Shopping (GET, gl=in)
│   │   │   ├── serper.py          #   Serper.dev Google Shopping (POST, gl=in)
│   │   │   └── searchapi.py       #   SearchAPI Google Shopping (GET, gl=in)
│   │   ├── aggregator.py          # raw API JSON -> PriceItem (+ currency -> INR)
│   │   ├── source_health.py       # circuit breaker: auto-skip dead / out-of-credit sources
│   │   ├── price_log.py           # price event logger + history (Upstash Redis REST)
│   │   ├── cache.py               # 5-min in-memory cache of responses
│   │   └── ml/                    # THE ML LAYER (see ML.md)
│   │       ├── matcher.py         #   product matching (TF-IDF + guards + clustering)
│   │       ├── deal_scorer.py     #   fair price + deal labels (median / MAD)
│   │       └── pipeline.py        #   glues them together, builds product groups
│   └── static/                    # index.html (the UI), favicon-32.png, apple-touch-icon.png (logo)
├── vercel.json                    # daily cron: /cron/log-prices at 02:30 UTC (08:00 IST)
├── tests/test_ml.py               # pytest tests for ML + circuit breaker
├── requirements.txt
└── .env.example                   # template for your local .env
```

## 3. Run locally

```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env              # then paste your keys into .env
uvicorn app.main:app --reload
```

- UI: http://localhost:8000
- API docs: http://localhost:8000/docs
- Health: http://localhost:8000/health

Run tests (no API keys or credits needed; they use fake data):
```bash
cd backend
pip install pytest
python -m pytest tests -q
```

## 4. Environment variables

| Variable | Source | Free allowance | Behaviour |
|---|---|---|---|
| `SERPAPI_KEY` | serpapi.com | 250 searches/month, **refills monthly** | Main source |
| `SERPER_API_KEY` | serper.dev | 2,500 on signup, then ~$1/1k | Second source; also returns the seller name (Flipkart, Croma…) |
| `SEARCHAPI_KEY` | searchapi.io | One-off free credits, **no refill** | Used until it runs out, then auto-skipped |

- Any source **without a key is skipped**. At least one key is required.
- **Each search costs 1 credit per active source.** With all three active, one search uses 3 credits.
- **Locally**, keys go in `backend/.env`. **On Vercel**, they go in Project → Settings → Environment Variables, followed by a **redeploy** (env changes don't apply to existing deployments).
- To retire a source for good, delete its key in Vercel and redeploy.

### Circuit breaker (`source_health.py`)
If a source fails with **HTTP 401 / 402 / 403 / 429**, or returns an error message mentioning credits, quota, limit, plan or an invalid key, it is **switched off for 6 hours** and not called again. Timeouts and 500 errors do **not** switch it off, since those are usually temporary.

The `/search` response shows what happened:
- `sources_ok`: sources that returned data
- `sources_failed`: sources that errored on this request
- `sources_disabled`: sources currently skipped, with the reason (e.g. `{"searchapi": "HTTP 402"}`)

The state is in memory, so a new Vercel instance starts fresh. That costs at most one wasted failed call per cold start, and failed calls don't use credits.

## 4b. Price history (event logger)

Stored in **Upstash Redis** (free tier) through its REST API, so no extra Python packages are needed. If the Redis env vars are missing, logging is skipped silently and the UI hides history.

**Setup (one time):** Vercel → credisearch_vercel → **Storage** → **Create / Connect** → **Upstash for Redis** (free) → connect it to this project. Vercel adds `KV_REST_API_URL` and `KV_REST_API_TOKEN` automatically. Optionally add `CRON_SECRET` (any random string). Then redeploy.

**What's logged:**
| Redis key | Type | Content |
|---|---|---|
| `events` | list | Every search, newest first (capped at 5,000): time, query, sources, top products with fair/min price, origin `user` or `cron` |
| `products` | hash | history key → product name |
| `price:<key>` | hash | `YYYY-MM-DD` → `{fair, min, max, offers, best_url}`; one point per product per day |

**Where the data comes from:**
1. Every user search, at no extra API cost.
2. **A daily cron** (`vercel.json`, 08:00 IST) that searches `TRACKED_PRODUCTS` (defaults in `history.py`) using **Serper only**, so it doesn't use SerpAPI's 250/month. About 5 credits a day, roughly 150 a month.

The history key is spelling-independent (`canonical_key` in `matcher.py`), so "Reno15 Pro" and "Reno 15 Pro" share one history.

**Endpoints:** `/history` (all products), `/history/{key}` (points + summary), `/history/events/recent?limit=50` (event log). Test the cron by hand: `curl -H "Authorization: Bearer $CRON_SECRET" https://credisearchvercel.vercel.app/cron/log-prices`

## 5. Deploy

Vercel is connected to this GitHub repo, so **deploying = pushing to `main`**.

```bash
git add -A
git commit -m "what changed"
git push
```

Vercel builds in about a minute. Check **Vercel → credisearch_vercel → Deployments**.

Vercel settings that must stay this way:
- **Root Directory:** `backend`
- Framework: FastAPI / Python (auto-detected from `app/main.py`)

## 6. API quick reference

`GET /search`

| Param | Default | Meaning |
|---|---|---|
| `q` | required | Product name, min 2 characters |
| `country` | `IN` | Google country code (sent as `gl`) |
| `limit` | `10` (max 40) | Number of offers returned in `results` |
| `hide_accessories` | `false` | Drop cases, chargers, protectors… |

Response: `results` (offers, cheapest first, each with `group_id`, `deal_label`, `deal_score`, `fair_price`, `vs_fair_pct`), `groups` (one per product: min/median/max price, best trusted offer, `is_accessory`, `is_refurbished`, `suspicious_offers`), plus `sources_ok` / `sources_failed` / `sources_disabled`.

Example: `/search?q=iphone 15 128gb&limit=20&hide_accessories=true`

## 7. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `/health` works but `/search` returns 503 | No keys set, or all sources disabled | Add keys in Vercel and redeploy; check credits on each dashboard |
| `/search` returns 502 | Every source errored on this request | Vercel → Logs → open the request and read the warning line (`serpapi failed: …`) |
| Prices look like ₹309 for a phone | A source returned US listings | Check the client sends `gl=in`; the aggregator converts `$` prices to INR |
| Env var added but nothing changed | No redeploy | Deployments → ⋯ → Redeploy |
| Same product split into many groups | Matching threshold too strict for that wording | Tune `SIMILARITY_THRESHOLD` in `ml/matcher.py` (see ML.md §6) |
| Different products merged | A guard is missing (new variant word) | Add the word to `VARIANT_WORDS` in `ml/matcher.py` and add a test |
| A part/accessory still shows | Word not in the lists and priced above 20% of the product | Add the word to `PART_WORDS` / `ACCESSORY_WORDS` in `matcher.py` |
| No history line in the UI | Redis not connected, or only 1 day of data so far | Check `/history`; connect Upstash (section 4b) |

## 8. Changing things safely

- **Add a new price source:** create `api_clients/<name>.py` with `search_products(query, country) -> dict`, add `normalize_<name>_results` in `aggregator.py` (it must return `PriceItem`s in INR), add the key to `config.py` and `.env.example`, and register it in `active_sources()` in `search.py`.
- **Tune the ML:** every knob is a constant at the top of `matcher.py` / `deal_scorer.py`. Change it, run the tests, and try a few real searches.
- **Always run `python -m pytest tests -q` before pushing.**

## 9. Known limits / ideas

- The cache is in memory: it is per serverless instance and lost on a cold start.
- The USD→INR rate is fixed at 83 (`aggregator.py`).
- History needs time: the trend line appears after 2+ days of data.
